# DDL standards — tables, columns, constraints, indexes, comments

Defaults for when `.pythia/conventions.md` says nothing. **The house always
wins**: if the schema names its primary keys `<TABLE>_PK`, write `<TABLE>_PK`.
`pythia similar` and `pythia ddl TABLE <NEIGHBOUR>` show what the house does.

## Datatypes

| Data | Use | Avoid, and why |
|---|---|---|
| Text | `VARCHAR2(n CHAR)` (≤ 4000, or 32767 with `MAX_STRING_SIZE=EXTENDED`) | `VARCHAR2(n)` = BYTE semantics: in AL32UTF8 a Vietnamese letter takes 2–3 bytes. `CHAR(n)` pads with blanks and breaks comparisons. `VARCHAR` may change meaning in a future release. |
| Long text | `CLOB` | `LONG` — deprecated, one per table, no functions on it. |
| Money, quantities | `NUMBER(p,s)` with the precision agreed | `FLOAT` / `BINARY_DOUBLE` — binary rounding in financial sums. |
| Counters, keys | `NUMBER(p)` or an identity column | Unbounded `NUMBER` for a key: no check on garbage values. |
| Flags | `NUMBER(1)` or `VARCHAR2(1 CHAR)` with a `CHECK`, or `BOOLEAN` on 23ai | A flag column with no `CHECK` — every spelling of "yes" arrives eventually. |
| Point in time | `DATE` (to the second) or `TIMESTAMP(6)`; `TIMESTAMP WITH TIME ZONE` when users span zones | Dates stored as `VARCHAR2` — every report re-parses them, and sorting breaks. |
| Binary | `BLOB` | `RAW(n)` above a few hundred bytes; `LONG RAW` ever. |
| JSON | `JSON` (21c+) or `CLOB CHECK (c IS JSON)` | Free text that is "usually JSON". |

## Keys and sequences

- **Every table has a primary key.** Surrogate (`ID`) by default; a natural
  key gets a `UNIQUE` constraint next to it.
- Identity columns (`GENERATED BY DEFAULT ON NULL AS IDENTITY`, 12c+) or a
  sequence (`S_<TABLE>`) — whichever the house already uses; never both in
  one schema without a reason.
- `CACHE` on sequences (default 20) is fine; `ORDER` only for RAC when the
  order is a requirement. Gaps are normal and not a bug.

## Constraint names (when the house has none)

| Kind | Name | Example |
|---|---|---|
| Primary key | `PK_<TABLE>` | `PK_T_ORDER` |
| Foreign key | `FK_<TABLE>_<PARENT>` | `FK_T_ORDER_LINE_T_ORDER` |
| Unique | `UK_<TABLE>_<COLS>` | `UK_T_ORDER_CODE` |
| Check | `CK_<TABLE>_<COL>` | `CK_T_ORDER_STATUS` |
| Index | `IX_<TABLE>_<COLS>` | `IX_T_ORDER_LINE_ORDER_ID` |

Oracle limits names to 30 bytes before 12.2 and 128 after — check the
version (`pythia doctor --db`) before writing a long one.

## Constraints

- `NOT NULL` wherever the business says "always" — it is also the
  optimizer's best friend.
- `CHECK` for small fixed value sets; a lookup table when the set changes or
  carries attributes.
- Foreign keys: always, unless the developer explicitly accepts the orphan
  risk. `ON DELETE CASCADE` only when the spec says children die with the
  parent — it is a silent mass delete otherwise.
- **Index every foreign key column** (leading columns of some index).
  Without it a parent `DELETE` or key `UPDATE` locks the entire child table.

## Indexes

- Index for the predicates the application really uses — `pythia grep` the
  table name and read the `WHERE` clauses before guessing.
- Composite order: equality columns first, the range column last; the most
  selective first among equals.
- A function in the predicate (`UPPER(name) = :x`) needs a function-based
  index on the same expression — or a rewritten predicate.
- Every index costs every `INSERT`/`UPDATE`/`DELETE`. On write-heavy tables,
  justify each one.
- Bitmap indexes: data warehouses with low concurrency only — on an OLTP
  table they serialize writers.
- `CREATE INDEX ... ONLINE` and online rebuilds need Enterprise Edition.

## Comments — the dictionary is the documentation

```sql
COMMENT ON TABLE t_order_line IS 'Order lines: one row per product per order';
COMMENT ON COLUMN t_order_line.qty IS 'Ordered quantity, in the product''s sales unit; > 0';
COMMENT ON COLUMN t_order_line.status IS 'N = new, C = confirmed, X = cancelled';
```

Say the meaning, the unit, the allowed values, and where the data comes from
when it is not obvious. `pythia comments T --scaffold` prints the statements
for every column still without one. `COMMENT ... IS` takes a literal, not an
expression: Vietnamese text goes in as written (pythia sends UTF-8).

## Audit columns (when the house has them, copy them exactly)

A common shape — **only** if the house uses it; `lint.required_columns` in
`conventions.json` makes it machine-checked:

```sql
created_by  VARCHAR2(128 CHAR) DEFAULT ON NULL SYS_CONTEXT('USERENV','SESSION_USER') NOT NULL,
created_at  TIMESTAMP(6)       DEFAULT ON NULL SYSTIMESTAMP NOT NULL,
updated_by  VARCHAR2(128 CHAR),
updated_at  TIMESTAMP(6)
```

## Template — one script, deploy order

```sql
-- 2026-10-14 - <author> - order lines for the order module
CREATE TABLE t_order_line (
  id        NUMBER(18)          GENERATED BY DEFAULT ON NULL AS IDENTITY,
  order_id  NUMBER(18)          NOT NULL,
  product   VARCHAR2(50 CHAR)   NOT NULL,
  qty       NUMBER(12,3)        NOT NULL,
  status    VARCHAR2(1 CHAR)    DEFAULT 'N' NOT NULL,
  CONSTRAINT pk_t_order_line PRIMARY KEY (id),
  CONSTRAINT fk_t_order_line_t_order FOREIGN KEY (order_id) REFERENCES t_order (id),
  CONSTRAINT ck_t_order_line_qty CHECK (qty > 0),
  CONSTRAINT ck_t_order_line_status CHECK (status IN ('N', 'C', 'X'))
);
CREATE INDEX ix_t_order_line_order_id ON t_order_line (order_id);
COMMENT ON TABLE t_order_line IS 'Order lines: one row per product per order';
COMMENT ON COLUMN t_order_line.id IS 'Surrogate key';
COMMENT ON COLUMN t_order_line.order_id IS 'Owning order (T_ORDER.ID)';
COMMENT ON COLUMN t_order_line.product IS 'Product code as sold';
COMMENT ON COLUMN t_order_line.qty IS 'Ordered quantity in the sales unit; > 0';
COMMENT ON COLUMN t_order_line.status IS 'N = new, C = confirmed, X = cancelled';
```

`pythia lint` it, then `pythia deploy` it: the split is per `;`, each
statement gets its own preview and journal entry, and one approval runs them
in this order.

## Errors you will meet

| Error | Meaning | Usual fix |
|---|---|---|
| ORA-00955 | name already used by an existing object | it exists — `pythia ls` it; a re-run of a half-applied script |
| ORA-01758 | NOT NULL column added to a non-empty table without default | add a default, or add nullable + backfill + `MODIFY NOT NULL` |
| ORA-02449 | unique/primary key referenced by foreign keys | drop or disable the child FKs first — destructive, ask |
| ORA-00054 | resource busy (another session holds the table) | `ALTER SESSION SET DDL_LOCK_TIMEOUT = 30`, or a quieter moment |
| ORA-01442 | column already NOT NULL | the change already landed — check before retrying |
| ORA-02264 | constraint name already used | names are schema-wide: pick another |
| ORA-01450 | maximum key length exceeded | index on too-wide `VARCHAR2(n CHAR)` columns — narrow or prefix |
